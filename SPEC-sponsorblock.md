# SponsorBlock: временный обход недоступного API

Согласованный сценарий: первый вопрос с явным согласием; опциональное
запоминание обхода; автоматическое восстановление вырезания без нового вопроса.

## Поведение и критерии приёмки

- Для YouTube с выбранными категориями распознанный сетевой сбой SponsorBlock
  предлагает скачать без вырезания, проверить снова или отменить.
- Закрытие и Esc отменяют загрузку; запоминание согласия изначально выключено.
- Настройка `SPONSORBLOCK_FAILURE_POLICY`: `ask` (по умолчанию), `bypass`, `stop`.
- Категории не меняются. Обход влияет только на текущую команду yt-dlp.
- После согласия `bypass` повторных окон/звуков нет; каждый обход пишется в лог
  и отмечается в прогрессе и результате.
- Состояние доступности живёт до закрытия приложения; согласие сохраняется
  в штатном конфиге. При новом запуске yt-dlp снова пробует SponsorBlock.
- После сбоя проверки API выполняются при новых загрузках с интервалами
  30/120/300 секунд и сетевым timeout=3; ручная проверка игнорирует интервал.
  Это socket timeout, не гарантия жёсткого общего дедлайна DNS/HTTP-запроса.
- Пустой ответ API/404 для отсутствующих сегментов не считается аварией.
- При восстановлении — одно сообщение; текущий обход не меняется на лету.
- Ошибки видео, ffmpeg и файлов не дают разрешения на обход SponsorBlock.
- HTTP 416 имеет независимый ограниченный повтор; обычный обход сохраняет
  `--continue`. Повторы не образуют бесконечный цикл.
- При ошибке API процесс останавливается сразу: некоторые версии yt-dlp
  откладывают ошибку предварительной обработки и продолжают скачивать видео.
  В момент вопроса процесс уже завершён. Неверный JSON считается сбоем API
  только на этапе получения отметок SponsorBlock.
- Для активного SponsorBlock `--match-filter -` ставит внутренний барьер перед
  передачей: stdin получает `y` только после сообщения о найденных отметках
  либо корректном отсутствии отметок. Это устраняет гонку между выводом ошибки
  и началом скачивания короткого видео. При обходе барьера нет, SponsorBlock
  явно отключается через `--no-sponsorblock`, включая внешние конфиги yt-dlp.
  Для разбора сообщений активного SponsorBlock принудительно заданы
  `--no-quiet --color never`, чтобы внешний quiet/ANSI-режим не оставил барьер закрытым.
- Tk обновляется только через `after`; ожидание ответа и сеть — в worker.
  Звук уважает существующую настройку; его сбой не ломает вопрос.
- Отменённый вопрос не возвращается, если новая загрузка очистила общий сигнал
  отмены. Таймер вопроса удаляется при закрытии; Esc/крестик снимают modal grab.
- Сбой сохранения согласия оставляет его в памяти и сообщает об этом;
  сбой уведомления о восстановлении не останавливает скачивание.

## Архитектура и стиль

Python 3.10+, CustomTkinter. Политика/классификация/доступность — `core/pipeline.py`;
команды и ограниченные повторы — `core/downloader.py`; отдельный вопрос —
`ui/components/sponsorblock_dialog.py`; координация — `ui/main_window.py`.
Стиль: `self.after(0, callback)` для Tk, `Popen(cmd, shell=False)` для запуска.

## Диагностика

Сводка суммирует завершённые дорожки по назначению, не усредняет мгновенные
скорости. Скорость завершённых медиа учитывает простои; при продолжении может
включать ранее полученные данные, что явно отмечено. `first progress` — первое
наблюдение прогресса, не сетевой TTFB. Подготовка включает ожидания/повторы.

## Проверки и границы

`python -m pytest tests/ -m "not integration"`

Сценарии с реальными yt-dlp/ffmpeg, локальным HTTP и Tk:
`python -m pytest tests/integration/test_sponsorblock_local.py tests/integration/test_sponsorblock_tk.py`

Эти тесты используют временный конфиг и синтетическое видео, не читают cookies,
не обращаются к YouTube. Проверяют HTTP 500/503/403/429, таймаут, обрыв, неверный
JSON, отсутствие отметок, согласие/отмену, следующий запуск и восстановление.
Файл после обхода сравнивается по SHA-256, результат вырезания — по длительности.

Unit-тесты мокают HTTP, Popen и Tk; проверяют согласие, отмену, сохранение,
восстановление, посторонние ошибки и статистику. Ручной запуск: `python main.py`.
Сборка при выпуске: `python build.py`. Не менять cookies/пользовательский конфиг,
не добавлять зависимости, не запускать реальные загрузки в unit-тестах.
